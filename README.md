## How to Read This Portfolio

Each project folder contains a **README** with a standardised structure: Problem, My Role, Key Decisions (with explicit tradeoffs), Results, and Documentation links.

Beyond the README, each project has depth documents reflecting how the work was actually done:

**ClickPoint projects** include `pitch.md`, `discovery.md`, and where relevant, `retrospective.md`, `prompt-strategy.md`, `scope-evolution.md`, and `compliance-integrations.md`. These reflect an iterative Scrumban process where discovery and delivery happen in parallel.

**Brasil Paralelo projects** include `pitch.md` in the Shape Up format (problem with data, appetite, solution, rabbit holes, no-goes, success metrics) and `post-mortem.md` where one exists with real content.

The format difference is intentional. Different companies, different methodologies, different contexts. The README structure is consistent; the depth documents reflect how I actually worked in each environment.

**If you have 2 minutes:** Read the MCP AI Assistant README and the GBB Subscription Transformation README.

**If you have 10 minutes:** Add the Integrations Ecosystem discovery.md (for the architecture debate) and the Media Downloads post-mortem.md (for the honest failure analysis).

**If you want to go deep:** The MCP AI Assistant has 6 documents covering discovery, prompt architecture, scope evolution, and a detailed retrospective explaining why the project took 10 weeks instead of 3.
